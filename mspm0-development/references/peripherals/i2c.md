# MSPM0 I2C

## Scope

本参考负责跨板卡的 MSPM0 I2C 电气、SysConfig、DriverLib 事务和验证方法。器件、封装、SDA/SCL、板载上拉与资源冲突必须从匹配的板级参考、当前原理图和本地 SysConfig metadata 获取。

## 选择与证据

1. 先确认控制器或目标设备角色、总线电压、速率、7 位地址、最大总线电容和时钟拉伸要求。
2. 优先使用 `/ti/driverlib/I2C` 硬件外设；只有现有工程架构或引脚约束明确要求时才使用软件 I2C。
3. 硬件 I2C 的 SDA/SCL 必须属于当前器件、封装和同一实例的合法复用，不能从其他板卡或封装复制。
4. 不把 7 位地址预先左移，除非当前 API 明确要求包含读写位的线上地址字节。

## 电气规则

- SDA 和 SCL 是开漏线；高电平来自上拉，软件 I2C 也必须通过释放线路产生高电平。
- 复核现有板载与外接上拉的并联值。上拉过弱会使上升沿过慢，过强会超过器件低电平灌电流能力。
- 上电后先检查两线空闲为高，再开始事务。持续低电平优先排查供电、共地、接反、复位和电平不兼容。
- 多主、时钟拉伸和热插拔只有在器件资料与当前设计明确需要时才启用或实现。

## SysConfig 与 DriverLib

1. 在 `.syscfg` 中创建 I2C 实例，设置角色、时钟源、目标速率和合法引脚。
2. 重新生成后核对实例、SDA/SCL、IRQ、DMA 与初始化名字；应用代码只使用当前 `ti_msp_dl_config.h/.c`。
3. 先实现带超时的阻塞事务，再根据吞吐量和并发需求升级为中断或 DMA。
4. 组合寄存器读取是否需要重复起始、是否允许中间 STOP，以及字节顺序，必须服从目标器件协议。
5. 控制器和目标设备 API、状态位及 FIFO 语义不同；不能只替换实例名复用另一角色的状态机。

## 错误与恢复

- 所有 ACK、BUSY、TX、RX 和完成等待都设置有限超时。
- 区分地址 NACK、数据 NACK、仲裁丢失、总线忙和软件超时；先保存首个错误，再复位事务状态。
- 只有目标器件资料允许时才尝试最多 9 个 SCL 脉冲和 STOP 的总线恢复。
- 恢复失败或线路仍被拉低时停止重试，避免无限循环掩盖接线或供电故障。

## 验证

1. 静态检查器件、封装、复用、上拉、电压、地址和共享资源。
2. 严格生成 SysConfig，并检查全部诊断与生成名字。
3. 编译后先读取一个有确定复位值的寄存器，或完成一个可回读写入。
4. 用逻辑分析仪检查 START、地址、ACK/NACK、数据、重复起始和 STOP。

SysConfig、编译或烧录成功都不能证明总线实物通信成立；只有目标器件响应或有效波形才是物理证据。
